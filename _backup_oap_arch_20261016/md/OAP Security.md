## 02 Field Issues

**보안 업무 현장에서 반복되는 6가지 문제**

같은 업무를 두고도 보안 업무를 수행하는 사용자와, 이를 검토·승인하는 관리자가 겪는 어려움은 다릅니다.

| Field Issue | 사용자 | 관리자 |
|---|---|---|
| **01** 보안 증적 제출 및 검토 | **수기 점검 항목마다 다른 증적, 제대로 제출하고 있을까요?** 수많은 수기 점검 항목별로 적합한 증적을 찾아 제출해야 하지만, 점검 기준을 정확히 이해하기 어렵고 잘못된 증적 제출로 재검토와 재제출이 발생할 수 있습니다. | **수기 점검 증적 검토에 소요되는 시간, 줄일 수 없을까요?** 점검 항목별로 제출된 증적을 보안 기준과 대조하여 개별 검토해야 하므로 많은 시간과 인력이 소요되며, 검토 업무가 집중될 경우 다른 보안 업무의 처리까지 지연될 수 있습니다. |
| **02** 보안 예외·유예 판단 | **보안 예외·유예 신청, 어떤 경우에 가능한가요?** 예외·유예 신청 대상 여부를 판단하기 어렵고, 보안 정책에 부합하는 신청 사유와 근거를 작성하는 데 많은 시간과 노력이 필요합니다. | **보안 예외·유예 신청, 어떤 기준으로 승인해야 할까요?** 다양한 신청 사유와 보안 위험을 검토하여 승인 여부를 판단해야 하지만, 반복되는 유사 사례와 복잡한 판단 기준으로 인해 업무 부담이 증가하고 일관된 의사결정이 어려워집니다. |
| **03** 보안 예외·유예 처리 | **단순한 예외·유예 신청도 승인까지 오래 기다려야 할까요?** 정형화된 저위험 사유로 신청하더라도 여러 검토·결재 단계를 거쳐야 하므로 승인까지 시간이 소요되고 후속 업무가 지연될 수 있습니다. | **저위험 예외·유예 신청도 매번 검토해야 할까요?** 반복되는 저위험 신청에도 동일한 검토·결재 절차가 적용되어 업무 부담이 증가하고, 중요한 보안 위험 검토에 집중하기 어렵습니다. |
| **04** 취약점 우선순위 판단 | **수많은 취약점, 무엇부터 조치해야 할까요?** 다수의 취약점을 제한된 시간 내에 조치해야 하지만, 우선순위를 잘못 판단하면 중요한 취약점의 조치가 지연되거나 누락될 수 있습니다. | **중요한 보안 위험, 우선순위 판단에서 놓치고 있지는 않을까요?** 취약점 심각도와 자산 중요도, 외부 위협 정보를 종합적으로 고려하기 어려워 실제 위험이 높은 취약점을 놓치거나 조치 우선순위를 잘못 설정할 수 있습니다. |
| **05** 보안 관리 사각지대 | **내가 관리해야 할 자산과 보안 점검 대상, 정확히 파악하고 있을까요?** 자산과 담당자 정보가 일치하지 않거나 최신 상태로 관리되지 않으면 점검 대상이나 조치해야 할 취약점을 놓칠 수 있습니다. | **자산 정보의 불일치로 중요한 보안 위험을 놓치고 있지는 않을까요?** 자산·정보시스템·담당자 간 정보 불일치와 누락으로 보안 점검 대상이 잘못 식별되거나 위험 관리의 사각지대가 발생할 수 있습니다. |
| **06** 보안 업무 문의 및 응대 | **보안 업무 문의, 언제까지 담당자의 답변을 기다려야 할까요?** 보안 점검 기준과 조치 방법, 예외·유예 신청 절차 등을 확인하려면 담당자에게 문의해야 하지만, 답변이 지연되면 업무 진행에도 차질이 발생할 수 있습니다. | **반복되는 보안 업무 문의, 일일이 답변해야 할까요?** 제한된 보안 운영 인력으로 다양한 문의에 대응해야 하므로 반복적인 안내 업무에 시간이 소요되고, 중요한 보안 관리 업무에 집중하기 어렵습니다. |

## 03 Why OAP Security

**AI 에이전트의 일관된 판단은 관계와 맥락에서 시작됩니다**

### 01 · Prioritize — 조치가 시급한 실제 위험을 먼저 식별합니다
“무엇부터 조치해야 하는가?” 조치가 시급한 실제 위험을 식별하고 우선순위와 근거를 제시합니다.

### 02 · Accelerate — 복잡한 보안 의사결정 시간을 줄입니다
“왜 검토와 판단에 오래 걸리는가?” AI 에이전트가 관련 정보를 탐색·분석하고 판단 근거를 제시해, 예외·유예 검토와 조치방안 결정 같은 보안 의사결정을 지원합니다.

### 03 · Standardize — 사람에 의존하지 않는 일관된 판단 근거를 둡니다
“왜 사람마다 판단이 다른가?” 온톨로지로 연결된 데이터와 관계를 기반으로 일관된 판단 근거를 제시합니다.

> **Ontology** — 특정 도메인의 개념과 속성, 개념 간 관계를 명시적으로 정의하여 데이터의 의미와 구조를 표현하는 모델

## 04 Key Capabilities

**주요 제공 서비스 및 기능**

OAP Console과 Inference API를 통해 AI 기반 보안 분석 서비스를 제공합니다.

### OAP Console — 보안 데이터를 연결하고, 관계를 보고, 위험을 분석합니다
`01 · 보안 운영자용 웹 콘솔`

| 항목 | 구분 | 내용 |
|---|---|---|
| **Data Integration** | 데이터 수집·연계·통합 | 보안 데이터를 수집·연계·통합하고 데이터 처리와 동기화를 자동화합니다. |
| **Ontology Modeling** | 객체·관계 모델링 | 보안 객체와 관계를 온톨로지로 모델링하고 시각화합니다. |
| **Vulnerability Topology** | 취약점 영향 분석 | 발견 취약점이 영향을 미치는 정보시스템·운영환경·인프라 자산을 제품/버전까지 6계층 영향 경로의 계층 그래프로 보여줍니다. |
| **AI Analysis** | 위험 분석·추론 | 온톨로지를 기반으로 보안 위험을 분석·추론하고 우선순위와 판단 근거를 제공합니다. |

### Inference API — 지금 쓰는 보안 시스템에서 AI 추론을 호출합니다
`02 · 레거시 시스템 · 전문 사용자용`

| 항목 | 구분 | 내용 |
|---|---|---|
| **System Inference API** | 외부 시스템 연계용 | 레거시와 외부 시스템에서 OAP Security의 AI 분석·추론 기능을 호출하는 시스템 연계 API입니다. |
| **User Inference API** | 허가된 사용자용 | 접근 권한을 받은 사용자가 로컬 PC의 개발·분석 환경에서 AI 분석·추론 기능을 직접 호출하는 사용자용 API입니다. |

### Human Review — AI 판단 기준은 조직이 정하고, 중요한 판단은 전문가가 검토합니다
`03 · Human-in-the-Loop`

| 항목 | 구분 | 내용 |
|---|---|---|
| **AI Configuration** | 판단 기준 설정 | 보안 정책·위험 기준·우선순위 등 AI 판단에 적용할 기준을 설정합니다. |
| **AI Analysis** | 분석 및 추론 | Ontology Context와 설정된 기준을 바탕으로 위험도·우선순위·판단 근거를 제시합니다. |
| **Human Review** | 전문가 검토 | 중요하거나 검토가 필요한 AI 판단을 담당자가 확인·수정·승인합니다. |
