OAP Security · Ontology Agent Platform

수많은 보안 이슈 중,
지금 먼저 조치해야 할 위험을 가려냅니다

자산·취약점·정보시스템·조직·보안정책을 연결하고, AI 에이전트가 위험의 관계와 맥락을 분석합니다. OAP Security는 조치 우선순위와 판단 근거를 제시하고 컴플라이언스 대응을 지원합니다.

KEY SUMMARY Security Domain Package · On-Premises LLM · 폐쇄망 운영 · Inference API로 기존 보안 업무에 연결
Field Issues

보안 업무 현장에서 반복되는 6가지 문제

같은 업무를 두고도 보안 업무를 수행하는 사용자와, 이를 검토·승인하는 관리자가 겪는 어려움은 다릅니다.

Field Issue구분현장의 질문
Field Issue 01보안 증적 제출 및 검토사용자

수기 점검 항목마다 다른 증적, 제대로 제출하고 있을까요?

수많은 수기 점검 항목별로 적합한 증적을 찾아 제출해야 하지만, 점검 기준을 정확히 이해하기 어렵고 잘못된 증적 제출로 재검토와 재제출이 발생할 수 있습니다.

관리자

수기 점검 증적 검토에 소요되는 시간, 줄일 수 없을까요?

점검 항목별로 제출된 증적을 보안 기준과 대조하여 개별 검토해야 하므로 많은 시간과 인력이 소요되며, 검토 업무가 집중될 경우 다른 보안 업무의 처리까지 지연될 수 있습니다.

Field Issue 02보안 예외·유예 판단사용자

보안 예외·유예 신청, 어떤 경우에 가능한가요?

예외·유예 신청 대상 여부를 판단하기 어렵고, 보안 정책에 부합하는 신청 사유와 근거를 작성하는 데 많은 시간과 노력이 필요합니다.

관리자

보안 예외·유예 신청, 어떤 기준으로 승인해야 할까요?

다양한 신청 사유와 보안 위험을 검토하여 승인 여부를 판단해야 하지만, 반복되는 유사 사례와 복잡한 판단 기준으로 인해 업무 부담이 증가하고 일관된 의사결정이 어려워집니다.

Field Issue 03보안 예외·유예 처리사용자

단순한 예외·유예 신청도 승인까지 오래 기다려야 할까요?

정형화된 저위험 사유로 신청하더라도 여러 검토·결재 단계를 거쳐야 하므로 승인까지 시간이 소요되고 후속 업무가 지연될 수 있습니다.

관리자

저위험 예외·유예 신청도 매번 검토해야 할까요?

반복되는 저위험 신청에도 동일한 검토·결재 절차가 적용되어 업무 부담이 증가하고, 중요한 보안 위험 검토에 집중하기 어렵습니다.

Field Issue 04취약점 우선순위 판단사용자

수많은 취약점, 무엇부터 조치해야 할까요?

다수의 취약점을 제한된 시간 내에 조치해야 하지만, 우선순위를 잘못 판단하면 중요한 취약점의 조치가 지연되거나 누락될 수 있습니다.

관리자

중요한 보안 위험, 우선순위 판단에서 놓치고 있지는 않을까요?

취약점 심각도와 자산 중요도, 외부 위협 정보를 종합적으로 고려하기 어려워 실제 위험이 높은 취약점을 놓치거나 조치 우선순위를 잘못 설정할 수 있습니다.

Field Issue 05보안 관리 사각지대사용자

내가 관리해야 할 자산과 보안 점검 대상, 정확히 파악하고 있을까요?

자산과 담당자 정보가 일치하지 않거나 최신 상태로 관리되지 않으면 점검 대상이나 조치해야 할 취약점을 놓칠 수 있습니다.

관리자

자산 정보의 불일치로 중요한 보안 위험을 놓치고 있지는 않을까요?

자산·정보시스템·담당자 간 정보 불일치와 누락으로 보안 점검 대상이 잘못 식별되거나 위험 관리의 사각지대가 발생할 수 있습니다.

Field Issue 06보안 업무 문의 및 응대사용자

보안 업무 문의, 언제까지 담당자의 답변을 기다려야 할까요?

보안 점검 기준과 조치 방법, 예외·유예 신청 절차 등을 확인하려면 담당자에게 문의해야 하지만, 답변이 지연되면 업무 진행에도 차질이 발생할 수 있습니다.

관리자

반복되는 보안 업무 문의, 일일이 답변해야 할까요?

제한된 보안 운영 인력으로 다양한 문의에 대응해야 하므로 반복적인 안내 업무에 시간이 소요되고, 중요한 보안 관리 업무에 집중하기 어렵습니다.
Why OAP Security

AI 에이전트의 일관된 판단은 관계와 맥락에서 시작됩니다

01 · Prioritize

조치가 시급한 실제 위험을 먼저 식별합니다

“무엇부터 조치해야 하는가?” 조치가 시급한 실제 위험을 식별하고 우선순위와 근거를 제시합니다.

02 · Accelerate

복잡한 보안 의사결정 시간을 줄입니다

“왜 검토와 판단에 오래 걸리는가?” AI 에이전트가 관련 정보를 탐색·분석하고 판단 근거를 제시해, 예외·유예 검토와 조치방안 결정 같은 보안 의사결정을 지원합니다.

03 · Standardize

사람에 의존하지 않는 일관된 판단 근거를 둡니다

“왜 사람마다 판단이 다른가?” 온톨로지로 연결된 데이터와 관계를 기반으로 일관된 판단 근거를 제시합니다.

Ontology — 특정 도메인의 개념과 속성, 개념 간 관계를 명시적으로 정의하여 데이터의 의미와 구조를 표현하는 모델

  • Ontology Modeling객체·관계 모델링보안 객체와 관계를 온톨로지로 모델링하고 시각화합니다.

02 · 레거시 시스템 · 전문 사용자용

  • User Inference API허가된 사용자용접근 권한을 받은 사용자가 로컬 PC의 개발·분석 환경에서 AI 분석·추론 기능을 직접 호출하는 사용자용 API입니다.
03 · Human-in-the-Loop

Human Review

  • AI Analysis분석 및 추론Ontology Context와 설정된 기준을 바탕으로 위험도·우선순위·판단 근거를 제시합니다.

Case 01 · Legacy System

긴급 취약점 대응

자산 담당자 · 자산 책임자

대규모 OS 환경에서 긴급 취약점의 우선 대응 대상을 식별합니다

업무 상황Windows Server 20대를 관리하는 담당자의 기존 취약점 관리 시스템에는 CCE·CVE를 포함한 60여 건의 미조치 취약점이 있습니다. 여기에 실제 악용이 확인된 긴급 취약점(CVSS 8.8, CISA KEV 등재) 알림이 들어오면, 담당자가 목록에서 긴급 대상을 직접 가려내야 합니다.

AI 분석취약점 정보 × KEV × 자산 × 정보시스템 × 운영환경 × 보안정책 × 조치이력을 분석해 기존 업무 화면에 추론 결과를 제공합니다.

  • 20대담당 자산
  • 18대영향 자산 — 영향 OS·버전 확인
  • 6대우선 확인 — PRD 운영환경·중요 정보시스템 연관·신규/반복/재발 여부
AI 판단 지원

수많은 취약점 알림을 일일이 확인하지 않고, AI가 업무 맥락을 분석해 우선 확인할 대상과 판단 근거를 제공합니다.

Case 02 · Legacy System

보안 예외·유예 신청 · 검토 · 승인

자산 담당자 · 자산 책임자 · 보안 운영자 · 보안 승인자

유사 예외·유예 사례를 자동으로 찾아 리드타임을 줄입니다

업무 상황조치가 어려운 운영 서버에 대해 90일 조치 유예 요청이 들어왔습니다. 기존에는 동일 CVE·동일 자산·동일 정보시스템의 과거 사례와 승인 기간·조건·보완조치, 현재 진행 중인 유예 여부를 담당자가 직접 찾아봐야 합니다.

AI 분석유예 요청 × 취약점 정보 × 자산 × 정보시스템 × 운영환경 × 예외·유예 이력 × 보완조치를 분석해 과거와 진행 중인 유사 사례를 비교·제시합니다.

  • 7건유사 사례 — 동일 취약점 3 · 동일 자산군 2 · 유사 위험조건 2
  • 3건현재 진행 중인 유예
AI 판단 지원

동일 CVE · 동일 OS · 동일 운영환경의 유예가 이미 승인되어 진행 중이라면 처음부터 다시 조사하지 않아도 됩니다. 반복적인 정보 탐색을 줄이고 검토 리드타임을 단축합니다.

Case 03 · OAP Console

긴급 보안 이슈 영향 분석

보안 운영자

신규 KEV 취약점이 발표되면 사내 영향 대상과 담당자를 바로 식별합니다

업무 상황가상화 관리 제품의 신규 KEV 취약점이 발표되었습니다. 사내 취약점 진단 결과를 받기 전, 외부 CVE·KEV 정보만으로 해당 제품을 쓰는 시스템이 있는지, 영향이 어디까지인지 먼저 확인해야 합니다.

AI 분석CVE → 제품/버전 → 설치 자산 → Host → 정보시스템 → 운영환경 → 담당 조직/담당자 순으로 온톨로지의 관계를 탐색합니다.

  • 12대영향 가능 자산 — PRD 8 · DEV 4
  • 7개관련 정보시스템 — 핵심 3 · 일반 4
  • 4개 / 6명즉시 알림 대상 조직 / 담당자
AI 판단 지원

신규 보안 위협이 생기면 제품·버전과 사내 자산의 관계를 분석해 영향 대상과 담당자를 신속하게 식별합니다.

Business Value

역할마다 달라지는 보안 운영

연결된 보안 데이터와 AI 추론으로 위험 판단부터 조치까지, 운영 효율과 의사결정의 일관성을 높입니다.

  • 자산 담당자빠른 위험 확인담당 자산의 취약점 위험도·긴급성·오탐 여부와 판단 근거를 직접 확인하고 조치합니다.
  • 자산 책임자효율적인 조치 관리담당 시스템의 취약점 위험과 우선순위를 직접 판단하고, 필요한 조치를 요청·관리합니다.
  • 보안 운영자핵심 위험 대응 집중반복적인 문의·안내를 줄이고 위험 분석과 예외·유예 등 핵심 보안 업무에 집중합니다.
  • 보안 승인자신속한 의사 결정위험도와 판단 근거를 확인해 주요 보안 사안을 신속하고 일관되게 승인합니다.

FAQ

자주 묻는 질문

도입을 검토하실 때 가장 많이 받는 질문을 모았습니다. 여기 없는 내용은 문의하기로 남겨 주십시오.

  • Q01인터넷이 차단된 폐쇄망에서도 쓸 수 있습니까?

    On-Premises LLM 기반으로 고객사 자체 서버·GPU 환경에 배포하므로 폐쇄망에서 운영합니다. 외부 LLM 서비스로 보안 데이터를 보내지 않습니다.

  • Q02LLM은 무엇을 씁니까? 우리 회사가 가진 LLM도 쓸 수 있습니까?

    검증된 Open-weight LLM 기반 Reference Model을 기본 제공하고, 고객사가 보유한 Custom LLM도 연계합니다. 신규 모델 적용과 GPU 최적화는 별도 기술지원 범위입니다.

  • Q03지금 쓰는 취약점 관리 시스템을 바꿔야 합니까?

    바꾸지 않습니다. Inference API로 기존 시스템에서 AI 분석·추론을 호출해, 담당자가 지금 쓰는 업무 화면에서 위험도와 판단 근거를 확인합니다.

  • Q04원천 시스템의 데이터 구조를 맞춰야 합니까?

    원천 시스템의 데이터 구조에 종속되지 않습니다. 수집한 데이터를 Ontology 객체와 관계로 매핑하며, API · DB · File 방식과 MCP Tool로 연계합니다.

  • Q05사내 시스템이나 다른 보안 솔루션도 연계할 수 있습니까?

    NVD · CISA KEV · EPSS, Qualys · Wiz · PrismaCloud, Jira · Confluence 연계 Tool을 기본 제공합니다. 고객사 내부 시스템은 Custom MCP Integration으로 확장하며 별도 구축 범위입니다. 고객사 시스템의 API 신규 개발은 포함되지 않습니다.

  • Q06AI의 판단을 그대로 따라야 합니까?

    아닙니다. 보안 정책·위험 기준·우선순위 등 판단 기준을 조직이 설정하고, 중요하거나 검토가 필요한 판단은 담당자가 확인·수정·승인합니다(Human-in-the-Loop).

  • Q07GPU는 어느 정도가 필요합니까?

    업무 규모에 따라 A100 80GB 1장(동시 추론 약 4–6건)부터 H200 1장(약 24건)까지 구성합니다. 32K Context 기준 참고 수치이며, 진단 단계에서 실제 요청량을 기준으로 산정합니다.

  • Q08도입 전에 검증해 볼 수 있습니까?

    긴급 취약점 대응 같은 대표 시나리오로 PoC를 진행하고 결과서를 드립니다. PoC 신청은 문의하기로 남겨 주십시오.
