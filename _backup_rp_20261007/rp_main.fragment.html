Field Issues

GPU 인프라 운영에서 반복되는 6가지 문제

GPU가 부족한지 판단하기 전에, 지금 가진 GPU가 어떻게 구축되고 어떻게 나뉘어 있는지부터 봅니다.

현장에서 생기는 문제 GenWorks-RP의 답
클러스터 하나를 구축하는 데 열흘이 걸린다 BMC로 서버의 OS 설치부터 초기 설정까지 자동화하고, Zone 용도에 맞는 Slurm·Kubernetes 환경을 자동으로 구성합니다.
부서별 GPU 배분을 엑셀과 구두 합의로 관리한다 조직×Zone 단위 계약으로 배분을 시스템에 등록합니다. 쿼터·기간·정책이 계약 조건 그대로 반영되고, 갱신과 만료까지 추적됩니다.
부서마다 노드를 나눠 두어 한쪽은 놀고 한쪽은 기다린다 노드를 부서별로 고정 분할하지 않습니다. 각 부서의 몫은 쿼터·우선순위·선점으로 보장하고, 유휴 자원은 다른 부서가 초과 사용합니다.
학습이 끝나 추론 수요가 늘어도 환경을 바꾸기 어렵다 운영 중에 Zone 구성을 바꿉니다. 실행 중인 워크로드를 내리지 않고 학습 Zone의 자원을 추론 Zone으로 옮깁니다.
장애가 나면 사람이 원인을 찾아 복구한다 GPU·Kubernetes·Slurm을 상시 헬스 체크하고, 정책에 따라 재시작·리셋·격리를 자동으로 수행합니다.
연구자의 모든 요청이 운영자를 거쳐야 한다 연구자 전용 셀프서비스 콘솔에서 작업 공간 생성부터 학습·서빙·사용량 확인까지 직접 수행합니다. 쿼터와 정책은 화면과 제출 폼에 자동 반영됩니다.

Architecture

공급 – 계약 – 수요를 잇는 자원 모델

인프라(공급)와 조직(수요)을 계약(배분)으로 연결해 GPU 자원을 체계적으로 관리합니다. 계약 조건을 바꾸면 자원 할당과 운영 환경에 바로 반영됩니다.

Zone
공급 · Supply

균질한 GPU 노드 풀 · 파티션. 단일 GPU 모델로 구성하고, 공용/전용 × 용도(Training·Inference)로 분류합니다. Cluster Management가 생성·구성합니다.

배분
연결 · Contract

조직×Zone의 자원 사용권. 쿼터·기간·정책이 계약 조건 그대로 시스템에 반영되며, 쿼터형(공용)과 노드 지정형(전용) 두 방식이 있습니다. Workload Management가 관리합니다.

조직
수요 · Demand

부서 · 프로젝트 · 사용자. 멤버의 그릇이자 배분을 받는 단위이며, 프로젝트 단위로 작업과 자산을 묶습니다. System Administration이 LDAP과 연동해 관리합니다.

통제 원칙노드를 부서별로 고정 분할하지 않습니다. 통제는 쿼터·우선순위·선점으로, 보장은 배분 단위의 예외(전용 Zone)로 합니다. 각 부서의 몫은 선점으로 확보하면서 유휴 자원은 다른 부서가 초과 사용할 수 있어 가동률이 유지됩니다.

용도에 따라 나누는 세 가지 Zone

  • Training공용 × AI 모델 학습. 대규모 배치 학습에 최적화된 공용 Zone으로, 쿼터형 배분으로 여러 조직이 공정하게 나눠 씁니다.
  • Inference공용 × AI 추론 서비스. 상주 서빙 워크로드를 위한 공용 Zone으로, 엔드포인트 단위의 추론 서비스가 배포됩니다.
  • Dedicated전용 × 단독 할당. 특정 팀·용도에 노드 단위로 단독 할당합니다. 물리적 전용이 계약 요건인 경우를 지원합니다.
Provisioning

고객 환경에 맞춰 유연하게 구성하고 확장합니다

Zone의 용도에 맞춰 소프트웨어 환경을 자동으로 구성합니다. 별도 구축 작업 없이 학습·추론·전용 Zone을 만들고, 운영 중에 다시 구성하고, 필요한 만큼 확장합니다.

  1. 01 · 구축OS 자동 설치BMC를 활용해 서버의 OS 설치부터 초기 설정까지 자동화하여 클러스터 구축 시간을 단축합니다.
  2. 02 · 구성자동 프로비저닝Zone 용도에 맞는 소프트웨어(Slurm·Kubernetes) 환경을 자동으로 구성하고 프로비저닝합니다.
  3. 03 · 운영무중단 재구성학습이 끝나 추론 수요가 늘면 Zone 구성을 바꿉니다. 실행 중인 워크로드를 내리지 않고 자원을 옮깁니다.
  4. 04 · 확장성노드 자동 편입새 노드를 연결하면 Zone에 맞춰 자동으로 구성·편입되어, 사용자와 워크로드가 늘어도 반복 구축 작업이 필요 없습니다.
Trust & Governance

엔터프라이즈 운영의 기반

통제와 추적성을 기반으로 설계해, 엔터프라이즈 환경에 필요한 운영 신뢰성을 제공합니다.

  • 인증OS 계정 · LDAP 연동별도 계정 체계 없이 조직의 OS 계정과 LDAP(AD) 도메인으로 로그인합니다. 인증 소스에서 삭제된 계정은 자동으로 탐지·차단됩니다.
  • 계약 정합계약 = 시스템쿼터·기간·정책이 계약 조건 그대로 시스템에 반영됩니다. 계약서와 화면이 같은 말을 하고, 갱신이 곧 배분 변경이 되어 어긋남이 생기지 않습니다.
  • 추적운영 이력 완전 보존워크로드 강제 종료, 계약 등록·변경, 정책 변경까지 모든 운영 개입에 실행자·대상·시각·사유가 기록되어 컴플라이언스 요구를 하나의 근거로 충족합니다.
  • 폐쇄망온프레미스 · 폐쇄망 대응외부 연결 없이 사내 인프라에서 완결됩니다. 내장 매뉴얼과 리포트 CSV/PDF 내보내기 등 폐쇄망 고객사의 운영 관행을 반영했습니다.

FAQ

자주 묻는 질문

도입을 검토하실 때 가장 많이 받는 질문을 모았습니다. 여기 없는 내용은 문의하기로 남겨 주십시오.

  • Q01부서별로 GPU 노드를 나눠 주지 않으면, 각 부서의 몫은 어떻게 보장됩니까?

    노드를 고정 분할하는 대신 쿼터·우선순위·선점으로 통제합니다. 각 부서의 몫은 선점으로 확보되고, 그 몫이 비어 있는 동안에는 다른 부서가 초과 사용합니다. 물리적 전용이 계약 요건이라면 노드 단위로 단독 할당하는 Dedicated Zone을 씁니다.

  • Q02학습용 자원을 추론용으로 바꿀 때 서비스를 멈춰야 합니까?

    멈추지 않습니다. 운영 중에 Zone 구성을 바꾸며, 실행 중인 워크로드를 내리지 않고 자원을 옮깁니다.

  • Q03서버를 증설하면 다시 구축 작업을 해야 합니까?

    새 노드를 연결하면 BMC 스캔으로 인벤토리에 잡히고, 해당 Zone에 맞춰 OS 배포부터 Slurm·Kubernetes 구성까지 자동으로 편입됩니다. 반복 구축 작업이 필요 없습니다.

  • Q04GPU 한 장을 여러 작업이 나눠 쓸 수 있습니까?

    MIG 프로파일을 구성하거나 템플릿으로 적용해 GPU를 분할합니다. 할당되지 않은 슬라이스는 경고로 알리고 회수합니다.

  • Q05별도의 계정 체계를 만들어야 합니까?

    필요 없습니다. 조직의 OS 계정과 LDAP(AD) 도메인으로 로그인하며, 인증 소스에서 삭제된 계정은 자동으로 탐지·차단됩니다. 역할은 운영자·부서 관리자·연구자로 나뉩니다.

  • Q06인터넷이 차단된 폐쇄망에서도 운영할 수 있습니까?

    외부 연결 없이 사내 인프라에서 완결되도록 설계했습니다. 매뉴얼이 제품 안에 들어 있고, 리포트와 감사 로그는 CSV/PDF로 내보냅니다.

  • Q07감사 대응에 필요한 기록이 남습니까?

    워크로드 강제 종료, 계약 등록·변경, 정책 변경까지 모든 운영 개입에 실행자·대상·시각·사유가 기록되고, 변경 전후 내용은 불변 저장됩니다. 조직별 사용 통계와 계약 이행 리포트도 기간별로 제공합니다.

  • Q08도입 전에 우리 환경에서 검증해 볼 수 있습니까?

    PoC로 대표 Zone을 구성해 배분 정책과 자동 조치를 실제로 검증하고, 결과를 PoC 결과서로 정리합니다. PoC 신청은 문의하기로 남겨 주십시오.
