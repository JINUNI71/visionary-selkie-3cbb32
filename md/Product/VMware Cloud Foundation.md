## 02 Why Softworks

**소프트웍스가 VMware Cloud Foundation을 다루는 방식**

### Why 01 — 구축 순간의 편의가 아닌, 2~3년 뒤의 운영 안정성을 기준으로 설계합니다

12년간 엔터프라이즈 가상화 시장을 지켜보며, 초기 아키텍처 설계가 2~3년 뒤 고객의 운영 비용과 장애 빈도에 얼마나 결정적인 영향을 미치는지 깊이 체감해 왔습니다. 단순 구축 단계의 편의성만 고려한 설계는 결국 운영 단계에서 고객의 부담으로 돌아옵니다. 소프트웍스는 시스템의 전체 라이프사이클을 통찰하여, 인수 후에도 안정적이고 효율적으로 유지 · 관리되는 최선의 아키텍처를 제시합니다.

![VMware Cloud Foundation 9의 통합 플랫폼 구조](assets/vcf/dia-vcf.svg)
*VMware Cloud Foundation 9의 통합 플랫폼 구조*

### Why 02 — 라이선스 구조 재설계를 전제로 가장 경제적인 아키텍처를 찾습니다

Broadcom의 새로운 패키지형 구독 체계에서는 기존 구성을 그대로 옮겨올 경우, 실제로는 쓰지 않는 고급 기능과 포괄적인 제품 묶음까지 포함되어 비용이 불필요하게 커질 수 있습니다. 소프트웍스는 워크로드 정밀 분석 → 클러스터 최적 재배치 → 필요한 패키지 규격 정밀 산정의 과정을 거쳐, 비용 낭비를 완벽히 차단하는 인프라 아키텍처와 라이선스 최적화 플랜을 동시에 제시합니다.

### Why 03 — 금융 · 공공의 까다로운 망분리 규제 대응부터 보안 감사까지 완벽히 지원합니다

금융 및 공공 분야의 인프라 구축은 단순 기술 구현을 넘어 엄격한 보안 지침과 규제 대응이 핵심입니다. 소프트웍스는 다수의 금융 · 공공 규제 프로젝트를 수행하며 축적된 노하우를 바탕으로, NSX 기반의 완벽한 가상화 망분리 환경을 구현합니다. 구축에 그치지 않고 실제 규제 점검과 보안 감사 과정에서 요구되는 증빙 자료 정리까지 꼼꼼히 챙겨, 규제 리스크를 줄인 안정적인 운용을 지원합니다.

### Why 04 — 가상화부터 컨테이너 · AI까지, 각 분야 전문 엔지니어가 하나의 팀으로 프로젝트를 성공시킵니다

VCF 도입 성공의 핵심은 가상화 계층은 물론, 그 위에서 동작하는 컨테이너 환경과 AI 워크로드까지 깊이 이해하는 전문 인력의 유무입니다. 소프트웍스는 인프라부터 상위 MLOps 플랫폼 개발 경험까지 겸비한 각 분야 전문 엔지니어를 보유하고 있습니다. 하부 가상화 레이어부터 상위 AI · 컨테이너 서비스 레이어까지 숙련된 전문 팀이 단일 창구로 밀착 지원하여, 복잡한 VCF 전환 프로젝트를 흔들림 없이 성공으로 이끕니다.

## 03 Scope of Work

| 단계 | 수행 범위 |
|---|---|
| **Assess** | 현 가상화 환경 진단 · 워크로드 인벤토리 · 라이선스 영향도 분석 · TCO 비교 (유지/전환/대체) |
| **Design** | VMware Cloud Foundation 아키텍처 설계 · 관리·워크로드 도메인 분리 · vSAN 스토리지 정책 · NSX 네트워크·망분리 설계 · 백업/DR 연계 설계 |
| **Build** | VCF Installer 기반 배포 · VCF Operations 표준 구성 · 보안 기준 적용 (CIS·기관 지침) · 성능 검증 |
| **Migrate** | 기존 vSphere / 타 하이퍼바이저 전환 · 변환(Converge) · 편입(Import) 경로 판단 · V2V 마이그레이션 · 단계별 전환 계획 및 롤백 기준 |
| **Operate** | 운영 인수인계 · 관리자 교육 · 정기 점검 체계 수립 · 기술 지원 체계 연결 |

## 05 Field Issues

| 현장에서 생기는 문제 | 소프트웍스의 해법 |
|---|---|
| “라이선스 체계가 변경되어 비용을 예측하기 어렵습니다” | 실제 워크로드 사용 패턴을 정밀 프로파일링하여 불필요한 과다 지출 없는 최적의 라이선스 패키지 규모를 산정합니다. 기존 환경 유지, VCF 전환, 타 솔루션 대체 등 3가지 시나리오에 대한 3개년 총소유비용(TCO)을 명확한 수치 데이터로 제시하여, 고객사가 가장 경제적이고 합리적인 의사결정을 내릴 수 있도록 지원합니다 |
| “vSAN 전환 이후 성능이 기대와 다릅니다” | 소프트웍스는 전환 전 현행 워크로드의 실제 I/O 특성을 정밀 측정하여 최적의 스토리지 정책(장애 허용 방식, 중복제거, 캐시 구성 등)을 설계합니다. 아울러 전환 완료 후 실제 성능 측정값을 사전 데이터와 비교 · 검증하여 기대에 부응하는 성능을 확보합니다 |
| “NSX를 도입했으나 망분리 규정 해석이 어렵습니다” | 금융 및 공공기관의 망분리 지침과 보안 규정은 해석과 적용이 매우 까다롭습니다. 소프트웍스는 다수의 금융 · 공공 망분리 프로젝트를 직접 완수한 경험을 바탕으로, NSX 기술을 활용한 최적의 보안 정책을 설계합니다. 나아가 실제 보안 점검과 감사 시 제출해야 하는 각종 증빙 문서와 산출물까지 한 번에 작성해 규제 대응 부담을 해소합니다 |
| “‘전환 중단 리스크’에 대한 걱정을 해소하여, 신속하고 안전한 의사결정을 돕습니다” | 인프라 전환 시 발생하는 장애 부담을 덜어내기 위해, 소프트웍스는 모든 단계마다 철저한 롤백 포인트를 마련합니다. 또한 소수 인원을 대상으로 한 파일럿 그룹 선전환과 업무 영향이 없는 안전한 시간대 작업을 원칙으로 삼아, 담당자와 경영진 모두 안심하고 결재할 수 있는 확실한 마이그레이션 프로세스를 제공합니다 |
| “기존 환경이 오래되어 VMware Cloud Foundation으로 전환할 수 있을지 판단하기 어렵습니다” | 소프트웍스는 기존 시스템의 구성 상태를 정밀 분석하여, 자원을 관리 도메인으로 통합하는 방식(Converge)과 워크로드 도메인으로 끌어오는 방식(Import) 중 최적의 경로를 먼저 가려냅니다. 이어 NSX 네트워크 추가와 스토리지 지원 범위를 꼼꼼히 검증한 뒤, 시행착오 없는 확실한 VCF 전환 방안을 제안합니다 |

## 06 VCF 구성요소 — VMware Cloud Foundation 9를 이루는 네 가지 구성요소

VMware Cloud Foundation은 구성요소 전체가 하나의 플랫폼으로 통합되어 동작합니다. 스토리지(vSAN)와 네트워크(NSX)를 소프트웨어로 정의하고, 그 위에서 자원 배포 자동화(Automation)와 통합 운영(Operations)이 하나의 콘솔로 자연스럽게 이어집니다. 컴퓨트 계층(vSphere · vCenter)은 vSphere Foundation 페이지에서 다룹니다. 아래는 각 구성요소의 핵심 동작 방식과, 성공적인 전환을 위해 소프트웍스가 사전에 정밀하게 검증하고 설계하는 기준입니다.

### vSAN — 서버 내장 디스크를 공유 스토리지로 구성합니다

서버 내부 디스크를 하나의 공유 스토리지로 통합하는 소프트웨어 정의 스토리지(SDS)입니다. 가상 머신(VM)별로 장애 허용(FTT)과 암호화 정책을 유연하게 설정할 수 있습니다. vSAN ESA 기술을 바탕으로 클러스터 전체에 항상 압축과 글로벌 중복제거(VCF 9.1 정식 지원)가 적용되어 스토리지 효율성을 극대화합니다. 또한 자체 Data Protection 기능을 통해 가상 머신당 최대 200개의 스냅샷을 보관하며, 다른 vSAN 데이터스토어로 데이터를 넘기는 vSAN 간 복제 기능(별도 라이선스)으로 차원 높은 데이터 보호 환경을 제공합니다.

![vSAN OSA와 ESA 아키텍처 비교](assets/broadcom/vcf-vsan-osa-esa.png)
*vSAN OSA와 ESA 아키텍처 비교*

**소프트웍스가 하는 일** — 외장 스토리지에서 vSAN으로 전환할 때 가장 자주 마주치는 문제는 구축 후 성능이 기대에 못 미치거나 용량이 급격히 줄어드는 현상입니다. 이는 초기 스토리지 정책 설계가 잘못되어 발생하는 문제입니다. 소프트웍스는 전환 전 워크로드의 I/O 특성을 정밀 측정하여 최선의 FTT, 캐시, 중복제거 정책을 사전에 확정합니다. 구축 후에는 실제 측정된 성능 수치를 사전 분석 데이터와 꼼꼼히 비교 · 검증한 종합 성능 검증 보고서를 제공하여, 용량과 성능 모두 만족스러운 vSAN 환경을 완성합니다.

### NSX — 네트워크와 보안을 소프트웨어로 정의합니다

NSX는 오버레이 네트워크와 분산 방화벽을 제공하여 가상 머신(VM) 단위의 정밀한 망분리(마이크로세그멘테이션)를 구현합니다. 특히 VCF 9부터는 vCenter 콘솔에서 VPC(가상 프라이빗 클라우드)를 직접 정의할 수 있어, 네트워크팀에 물리 VLAN 설정을 새로 요청하는 번거로움 없이 워크로드에 네트워크를 즉시 할당할 수 있습니다. 아울러 신규 배포 시 기본 적용되는 NSX Enhanced Data Path 모드를 통해 동일한 네트워크 트래픽을 훨씬 적은 CPU 코어로 효율적으로 처리합니다. 소프트웍스는 이 기능의 전제 조건인 보유 서버 NIC의 기술 호환성을 사전에 정밀 검증하여, 리스크 없는 최적의 네트워크 환경을 완성합니다.

**소프트웍스가 하는 일** — 전자금융감독규정과 공공 망분리 지침이 적용되는 인프라 현장에서는 NSX 기술 설치를 마치고도 복잡한 보안 규정을 어떻게 반영해야 할지 몰라 프로젝트 진척이 중단되는 경우가 많습니다. 바로 이 구간이 소프트웍스가 전문성을 발휘하는 핵심 영역입니다. 소프트웍스는 단순 기술 지원을 넘어 규정 해석 → NSX 분산 방화벽 정책 설계 → 감사 대응 증빙 작성까지를 하나의 일관된 범위로 직접 수행합니다. 얽혀 있는 규제 이슈를 명쾌하게 해소하고, 감사 대응까지 빈틈없는 가상화 보안 환경을 완성합니다.

### VCF Automation — 강력한 워크플로 오케스트레이션으로 복잡한 IT 프로세스를 자동화합니다

VCF Automation은 자원 요청부터 승인, 배포에 이르는 모든 절차를 시스템화합니다. 특히 시스템 간 연계와 복잡한 작업 단계를 하나로 묶어주는 워크플로 오케스트레이션을 통해 IT 운영의 효율을 극대화합니다. 현업은 카탈로그를 통해 자원을 손쉽게 사용하고, 관리자는 정책과 비용을 통합 관리할 수 있습니다. VCF 9 환경에서는 테넌트 관리가 단일 VCF 콘솔로 통합되어 더욱 직관적입니다. 기존 vSphere, vRA, Cloud Director 등 어떤 환경에서 출발하든 전환 경로와 작업 중단 구간이 상이하므로 사전 진단이 필수적입니다. 소프트웍스는 고객의 환경에 맞춘 최적의 오케스트레이션 아키텍처와 리스크 없는 전환 로드맵을 제시합니다.

*Organization · Project · VPC · Namespace 테넌시 모델*

*셀프서비스 카탈로그 화면*

**소프트웍스가 하는 일** — 소프트웍스는 메일과 엑셀에 의존하던 비효율적인 자원 요청 방식을 VCF Automation 기반의 자동화 프로세스로 전환합니다. 단순히 툴을 설치하는 것에 그치지 않고, 고객사의 실제 승인 라인과 신청 양식을 블루프린트로 정밀하게 이관합니다. 또한 사내 ITSM 및 계정 관리(AD · LDAP) 등 기존 기간계 시스템과 VCF Automation을 유기적으로 연동하여, 결재 완료 즉시 자원이 자동으로 프로비저닝되는 통합 오케스트레이션 환경을 구축합니다.

### VCF Operations — 흩어져 있던 관리 영역을 단일 콘솔로 통합해 운영 가시성을 높입니다

시스템 수명주기를 관리하는 플릿 라이프사이클(계획 · 스케줄 · 업그레이드)부터 인프라 성능 최적화, 애플리케이션 및 네트워크 토폴로지 분석, 보안 대시보드에 이르기까지 운영에 필요한 모든 기능을 한 화면에서 제공합니다. 멀티 사이트 환경의 vCenter와 가상 자원을 통합 조회할 수 있음은 물론, 복잡했던 소프트웨어 구독 체계와 기술 지원 창구까지 단일화하여 기업의 IT 거버넌스를 강력하게 뒷받침합니다.

**소프트웍스가 하는 일** — 기본 대시보드 화면을 설정만 해 둔 환경은 운영 단계에서 거의 열람되지 않습니다. 진정한 인프라 관제는 고객사의 실제 운영 기준과 맞물려야 비로소 가치를 발휘합니다. 소프트웍스는 구축 직후 고객의 운영 기준에 맞춰 지표 항목을 새롭게 재구성합니다. 아울러 초기 3개월 동안 정기 점검 항목과 알림 임계값을 현업 담당자와 함께 조율하고 다듬어 나갑니다. 이 과정을 거친 후에야 비로소 운영 조직이 안심하고 사용할 수 있는 인수인계가 이루어집니다.
