## 02 WHY SOFTWORKS

**소프트웍스가 VCF를 다루는 방식**

1. **구축과 운영이 분리되지 않습니다**
   설계한 사람이 운영까지 맡습니다. SK텔레콤 IDC 3개 국사(인천·보라매·대전)를 직접 운영하며,
   구축 단계의 설계 판단이 3년 뒤 운영 비용으로 어떻게 돌아오는지를 아는 조직입니다.

2. **라이선스 재설계를 전제로 접근합니다**
   Broadcom의 코어 기반 구독 체계에서는 "쓰던 대로 옮기는 것"이 가장 비싼 선택입니다.
   워크로드 프로파일링 → 클러스터 재배치 → 코어 산정까지, 아키텍처와 라이선스를 함께 설계합니다.

3. **VCF의 빈 곳을 자사 제품으로 메웁니다**
   SDDC Manager가 커버하지 못하는 멀티 클러스터 통합 가시성과 운영 자동화는
   자사 제품 **Cloud-V**(보안기능확인서 획득, 2025.09)로 보완합니다. 총판이 아니라 플랫폼을 만드는 회사입니다.

4. **전환은 무중단이 기본값입니다**
   운영 중인 서비스 위에서 진행하는 전환을 전제로 절차를 설계합니다.
   전환 실패 시 되돌릴 수 있는 지점(Rollback Point)을 단계마다 확보한 뒤에만 다음 단계로 넘어갑니다.

## 03 SCOPE OF WORK

| 단계 | 소프트웍스 수행 범위 |
|------|---------------------|
| **ASSESS** | 현 가상화 환경 진단 · 워크로드 인벤토리 · 라이선스 영향도 분석 · TCO 비교(유지/전환/대체) |
| **DESIGN** | VCF 아키텍처 설계 · 관리/워크로드 도메인 분리 · vSAN 스토리지 정책 · NSX 네트워크 및 망분리 설계 · 백업/DR 연계 설계 |
| **BUILD** | Cloud Builder 기반 자동 배포 · SDDC Manager 표준 구성 · 보안 기준(CIS/기관 지침) 적용 · 성능 검증 |
| **MIGRATE** | 기존 vSphere / 타 하이퍼바이저 → VCF 전환 · V2V 마이그레이션 · 단계별 전환 계획 · 무중단 전환 |
| **OPERATE** | 라이프사이클 관리(패치·업그레이드) · 24×7 모니터링 · 정기 점검 · 장애 대응 · Cloud-V 기반 통합 운영 |

## 04 DELIVERY METHOD

**5단계 구축 절차 — 단계마다 산출물로 검증합니다**

| STEP | 수행 내용 | 산출물 |
|------|-----------|--------|
| 01. 현황 진단 | 자원 사용률·워크로드 특성·장애 이력 분석 | 인프라 진단 보고서, 워크로드 인벤토리 |
| 02. 아키텍처 설계 | 도메인 구성, 이중화, 확장 시나리오 | 아키텍처 설계서, 이중화·확장 계획서 |
| 03. 구축 및 검증 | 자동 배포, 보안 설정, 성능·장애 시험 | 구축 결과서, 성능 시험 성적서, 장애 시나리오 검증서 |
| 04. 전환 | 파일럿 → 단계 전환 → 안정화 | 전환 계획서, 전환 결과 보고서, 롤백 절차서 |
| 05. 이행 및 운영 | 운영 인수인계, 교육, 정기 점검 체계 수립 | 운영 매뉴얼, 관리자 교육 자료, 운영 SLA |

## 05 FIELD ISSUES → OUR ANSWER

**VCF 전환 현장에서 반드시 마주치는 5가지**

| 현장에서 생기는 문제 | 소프트웍스의 해법 |
|---------------------|------------------|
| 라이선스 체계 변경으로 비용이 예측되지 않는다 | 워크로드 프로파일링 기반 코어 산정, 유지/전환/대체 3안의 3개년 TCO를 숫자로 제시 |
| vSAN 전환 후 성능이 기대와 다르다 | 전환 전 워크로드 I/O 특성 측정 → 스토리지 정책(FTT·중복제거·캐시) 설계 → 전환 후 실측 비교 |
| NSX를 깔았지만 망분리 규정 해석이 어렵다 | 금융·공공 망분리 구축 경험 기반의 정책 설계, 감사 대응 산출물까지 함께 작성 |
| 전환 중단 리스크로 결재가 나지 않는다 | 단계별 롤백 포인트 확보 + 파일럿 그룹 선전환, 업무 영향 없는 시간대 전환 |
| 구축은 끝났는데 운영 인력이 없다 | 운영 인수인계 + 관리자 교육 + Managed Operation 연계, IDC 운영 조직이 그대로 이어받음 |
