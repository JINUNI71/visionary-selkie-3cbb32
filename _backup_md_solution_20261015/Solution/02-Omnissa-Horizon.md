## 02 Why Softworks

**소프트웍스가 Omnissa Horizon를 다루는 방식**

### Why 01 — 신규 구축보다 재구축 수행 이력이 많습니다

대형 생명보험사 업무망 VDI 재구축, 증권 IT 인프라 전문기관의 사내 데스크톱 가상화 재구축, 자원·에너지 공공기관 VDI 재구축을 수행했습니다. 이미 운영 중인 VDI를 사용자 불만 없이 교체하는 작업은 신규 구축과 난이도가 전혀 다릅니다.

### Why 02 — 사이징을 측정값으로 확정합니다

PoC·BMT 단계에서 실제 사용자 그룹의 CPU·메모리·IOPS·동시접속 패턴을 측정하고, 부팅 스톰과 로그인 스톰을 재현한 뒤 사이징을 확정합니다.

### Why 03 — 규제 대응 산출물까지 포함합니다

금융 전자금융감독규정과 공공 망분리 지침에 대응하는 구성과 증빙 산출물을 구축 산출물에 포함합니다.

### Why 04 — 사용자 변화관리를 프로젝트 범위에 포함합니다

VDI 실패 요인의 절반은 기술이 아닌 사용자 저항에서 발생합니다. 전환 전 안내와 사용자 교육, 초기 집중 헬프데스크 운영을 수행 범위에 포함하여 설계합니다.

## 03 Scope of Work

| 단계 | 수행 범위 |
|---|---|
| **Assess** | 사용자 그룹 분류 · 업무 프로파일 분석 · 기존 VDI 문제점 진단 · 규제 요건 정리 |
| **Design** | 사이징 및 이중화 설계 · 마스터 이미지 / Instant Clone 전략 · 프로필 보존 범위 정의 · RDSH 게시 앱 · 세션 데스크톱 설계 · 망분리·자료전송 연계 설계 · GPU 할당 설계 |
| **Build** | Connection Server / UAG 구축 · 이미지 빌드 · RDS 팜 구성 · 앱 호환성 시험 · 보안 정책 적용 · 부하 시험 |
| **Migrate** | 기존 VDI → 신규 VDI 그룹별 전환 · 사용자 데이터 이행 · 병행 운영 기간 관리 |
| **Operate** | 이미지 정기 업데이트 · 사용자 지원 · 성능 모니터링 · 증설 계획 수립 |

## 04 Knowledge Base

**재구축을 반복하며 축적한 판단 기준을 보유하고 있습니다**

VDI는 구축 이후에도 3~5년 주기로 다시 설계해야 하는 시스템입니다. 소프트웍스는 신규 구축보다 재구축 사업을 더 많이 수행해 왔으며, 그 과정에서 사용자 그룹 분류와 유지할 이미지 수, 데이터 이관 방식에 대한 판단 기준을 축적했습니다.

| 지표 | 내용 |
|---|---|
| **12년** | 데스크톱 가상화 구축 이력 |
| **금융 · 공공 · 연구 · 교육** | 산업별 규제 요건 적용 이력 |
| **신규 + 재구축** | 기존 VDI 전환 경험 보유 |
| **PoC / BMT** | 실측 기반 사이징 방법론 |

**축적된 자산**

- 업무 유형별 사용자 그룹 정의 템플릿
- 그룹별 자원 사용 패턴 기준값
- 로그인 · 부팅 스톰 재현 시험 시나리오

- 사용자 이관 가이드 · 교육 커리큘럼
- 1 / 2 / 3차 장애 대응 절차서

## 07 Horizon 구성요소 — Horizon을 구성하는 다섯 가지 요소

Horizon은 단일 제품이 아니라 데스크톱 배포 · 앱 전달 · 접속 경로 · 화면 전송 · 단말 보안이 맞물려 동작하는 구성요소의 집합입니다. 각 구성요소의 역할과 구성요소별로 소프트웍스가 결정하는 사항을 정리했습니다.

### Instant Clone — 마스터 이미지 한 장으로 데스크톱을 생성합니다

부모 VM에서 메모리·디스크를 공유하는 방식으로 수십 초 안에 데스크톱을 생성하고, 로그오프 시 초기 상태로 복원합니다. 이미지를 갱신하면 다음 로그인 시점부터 전체 사용자에게 일괄 반영됩니다.

![마스터 이미지에서 Instant Clone이 생성되기까지 디스크와 메모리가 각각 다르게 분기되는 구조 (Omnissa 제공 도식)](../assets/horizon/hz-instant-clone.png)
*마스터 이미지에서 Instant Clone이 생성되기까지 디스크와 메모리가 각각 다르게 분기되는 구조 (Omnissa 제공 도식)*

*도식 — 마스터 이미지에서 Instant Clone으로 데스크톱 풀을 생성하고 초기화하는 흐름*

**소프트웍스가 하는 일** — 마스터 이미지에 포함할 애플리케이션과 RDSH 게시 앱으로 분리할 항목을 구분하는 결정이 운영 난이도를 좌우합니다. 업무 그룹별 애플리케이션 목록과 정책을 먼저 확정한 뒤 이미지 수를 설계합니다.

### 앱 가상화 · RDSH — 앱 구성이 동일한 서버를 하나의 팜으로 구성하고 세션 단위로 분할하여 제공합니다

RDS 팜은 앱 구성이 동일한 Windows Server 호스트의 집합이며, 그 위에 게시 앱 풀과 세션 기반 데스크톱 풀을 구성합니다. 하나의 서버 OS에서 다수 사용자의 세션이 함께 구동되므로 사용자당 OS·메모리 오버헤드가 전용 데스크톱보다 작으나, 다중 인스턴스를 지원하지 않는 앱은 멀티세션 모드가 동작하지 않아 앱 실행마다 독립 세션을 생성하는 Isolated App Launch로 우회합니다. 팜 또한 데스크톱 풀과 동일하게 골든 이미지에서 Instant Clone으로 생성하여 원래 상태로 리프레시하거나 새 이미지로 교체합니다.

*도식 — 앱 조합을 팜 경계로 삼는 RDS 팜 구조와 애플리케이션 풀 · 게시 데스크톱 풀 구성*

**소프트웍스가 하는 일** — 팜으로 전환할 업무와 전용 데스크톱에 유지할 업무를 설계 착수 전에 목록으로 확정합니다. 대상 앱은 Windows Server에서의 지원 및 동작 여부와 동일 호스트에 다수 세션이 구동될 때의 설정·파일 경로 충돌 여부를 먼저 확인하여 검증 결과서로 남기고, 조건을 충족하지 못한 앱은 격리 실행으로 우회할지 전용 데스크톱으로 분리할지 앱 단위로 결정합니다. 앱 조합이 그대로 팜 경계가 되므로 앱 조합표를 먼저 작성하여 팜 수와 골든 이미지 수를 정하고, 호스트당 최대 세션 수는 레퍼런스 가정값을 그대로 적용하지 않고 PoC·BMT로 확정합니다. 비용 산출서에는 Horizon과 별개로 필요한 Microsoft RDS CAL과 RD 라이선싱 서버를 사용자/장치 모드 선택까지 포함하여 반영합니다.

### UAG · 접속 인증 — 외부 접속을 통제된 경로로 받습니다

Unified Access Gateway가 DMZ에서 외부 접속을 받아 내부 연결 서버로 중계합니다. 내부망을 직접 개방하지 않고 인증과 암호화를 게이트웨이에서 처리합니다.

![Horizon 8 논리 구성 (Omnissa 제공 도식)](../assets/horizon/hz-logical-components.png)
*Horizon 8 논리 구성 (Omnissa 제공 도식)*

![인증서를 발급하여 암호 재입력 없이 데스크톱에 로그인하는 True SSO 구조](../assets/horizon/hz-true-sso.png)
*인증서를 발급하여 암호 재입력 없이 데스크톱에 로그인하는 True SSO 구조*

*도식 — 포탈 · 2차 인증 · 연결 서버 · 데스크톱 할당으로 이어지는 접속 흐름*

**소프트웍스가 하는 일** — 포탈 접속 → 1차 인증 → OTP 2차 인증 → 연결 서버 → 데스크톱 할당까지의 흐름을 고객 인증 체계에 맞춰 설계합니다. 외부 사용자에게만 OTP를 적용하는 조건부 정책도 이 단계에서 결정합니다.

### Blast Extreme — 회선 품질이 낮은 환경에서도 화면 전송을 유지합니다

회선 품질에 따라 코덱과 전송 방식을 조정하는 전용 원격 프로토콜입니다. 회선 품질이 저하되면 화질을 낮추어 반응성을 유지하며, GPU가 탑재된 환경에서는 인코딩을 GPU에서 처리합니다.

![외부 접속 시 구간별로 개방이 필요한 Blast 포트 (Omnissa 제공 도식)](../assets/horizon/hz-external-blast-ports.png)
*외부 접속 시 구간별로 개방이 필요한 Blast 포트 (Omnissa 제공 도식)*

*도식 — 회선 품질에 따라 코덱·화질·인코딩 경로를 조정하는 적응 구조*

**소프트웍스가 하는 일** — 지점·재택·모바일과 같이 회선 조건이 다른 그룹을 구분하고 그룹별 프로토콜 정책과 대역폭 기준을 수립합니다. 기준값은 구축 전 실제 회선에서 체감 성능을 측정한 결과로 확정합니다.

### 보안 정책 — 데이터를 단말에 남기지 않습니다

클립보드 통제, USB 등 주변장치 통제, 화면 캡처 방지와 워터마크, 전 구간 통신 암호화를 정책으로 적용합니다.

*도식 — 구간 암호화 · 주변장치 · 클립보드 · 워터마크로 구성되는 보안 통제 4축*

**소프트웍스가 하는 일** — 금융 전자금융감독규정과 공공 망분리 지침에 맞춰 통제 항목을 매핑하고, 파일 반출입은 승인 절차를 거치도록 포탈과 연계합니다. 감사 대응 증빙 산출물까지 포함합니다.

> 출처 — 도식 출처는 Omnissa Tech Zone 공개 레퍼런스 아키텍처 문서(Horizon 8 architecture)입니다. 벤더가 공개한 원본 도식은 해상도만 조정하여 그대로 수록했으며, 그 아래 도식은 소프트웍스가 국내 구축 기준으로 다시 작성한 것입니다.

## 10 Operation & Support

**전환 직후 3개월의 운영이 VDI 정착을 결정합니다**

VDI는 전환 직후에 사용자 문의가 집중됩니다. 구축을 수행한 엔지니어가 전환 이후 대응 창구를 담당하며, 고객 운영 조직이 자체적으로 관리할 수 있는 수준에 도달할 때까지를 지원 범위로 설정합니다.

- 1 / 2 / 3차 단계별 장애 대응 체계
- 복합 장애 시 제조사 · 전문 인력 합동 대응
- 정기 예방 점검 (월 · 분기 · 반기)
- 마스터 이미지 정기 배포 대행
- 성능 리포트 정기 제공
- 운영자 · 사용자 실무 교육 및 교육 영상 제공
- 증설 · 재설계 컨설팅
- 데스크톱 DR 구성 (예비 센터 전환 절차 수립 · 전환 시험)
