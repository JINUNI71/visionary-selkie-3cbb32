## 02 Why Softworks

**소프트웍스가 CloudX를 다루는 방식**

### Why 01 — Cloud X 공식 구축 파트너입니다

Cloud X는 SK브로드밴드가 직접 개발·운영하는 서비스이며, 소프트웍스는 이 서비스를 고객 환경에 구축해 온 공식 파트너입니다. 제품을 유통하는 총판이 아니라 서비스 제공사와 함께 고객 환경을 설계하는 구축 조직입니다.

### Why 02 — 관리 포털을 직접 개발했습니다

SK브로드밴드 Cloud PC Admin 포털의 운영 및 고도화를 수행했습니다. Cloud X는 Admin Portal의 고객별 Customizing을 지원하며, 해당 커스터마이징을 실제로 구현한 조직이 소프트웍스입니다. 외산 VDI는 하이퍼바이저 관리 도구 · 브로커 관리 도구 · 별도 포털을 오가며 운영해야 하지만, Cloud X는 Admin Portal 한 화면에서 운영이 이루어집니다.

*도식 — 단일 관리 도구 운영과 다중 도구 운영 방식의 비교*

### Why 03 — 공공 도입 요건을 제품과 절차 양쪽에서 충족합니다

제품은 국가정보원 보안기능확인서와 GS 인증 1등급을 보유하고, MSA·컨테이너·오토스케일링 등 정부 권고 Cloud Native 요건을 충족합니다. 도입 절차는 조달청 디지털서비스몰 MAS 계약으로 단축됩니다.

### Why 04 — 외산 VDI 라이선스 리스크의 현실적 대안을 설계합니다

사용자 그룹별로 외산 VDI와 Cloud X를 병행·분리 배치하는 전환 시나리오를 설계합니다. 두 플랫폼을 모두 구축한 경험을 근거로 그룹별 배치 기준을 판단합니다.

## 04 Knowledge Base

**착수 전에 현황을 실측하고 산식으로 규모를 산정합니다**

VDI 전환의 성패는 착수 이전 단계에서 절반이 결정됩니다. 소프트웍스는 대형 전환 사업에서 설계 착수 전 수개월을 현황 파악에 투입하며, 그중 한 달가량은 실장비 PoC로 품질을 검증합니다. 근거 없이 산정한 규모는 이후 비용 초과나 성능 저하로 이어집니다.

| 지표 | 내용 |
|---|---|
| **실장비 PoC** | 관리·운영 서버와 스토리지를 실제로 구성해 검증 |
| **산식 기반 사이징** | 가상화 비율 · 여유율까지 근거 기록 |
| **공공 · 금융 · 의료** | 산업별 규제 요건 적용 이력 |
| **Admin Portal 개발** | 플랫폼 내부 구조까지 직접 다룬 경험 |

**축적된 자산**

- PoC 검증 항목 체크리스트 (서버 · 스토리지 · 네트워크 · 업무 호환성)
- 사용자당 네트워크 점유 대역폭 기준값 (약 200Kbps)
- VM 표준 사양 기준 (OS 디스크 70GB, Windows 11 업그레이드 고려)
- 체감 품질 기준선 (가상 PC 접속 20초 내외)
- 서버 대수 산정 산식 (동시접속 VM × 표준 사양 ÷ 서버 수용량)
- 가상화 비율 적용 기준과 CPU 여유율 확보 근거
- 스토리지 유효 용량 산정 (RAID · 중복제거 · 예비율 · 스냅샷)
- 망분리 환경 VDI Zone 배치 패턴
- 보안적합성 검증 절차 (착수 단계 편성)

## 05 Field Issues

| 현장에서 생기는 문제 | 소프트웍스의 해법 |
|---|---|
| “외산 VDI 라이선스 비용이 통제되지 않습니다” | 사용자 그룹별로 외산과 Cloud X를 나눠 배치하고 단계적으로 전환합니다. 계정 체계는 두 방식 모두 가능하며, 이미 Active Directory를 운영 중이면 그대로 연동하고 신규 구축이라면 Non-AD 구성으로 설계해 AD용 Windows Server 라이선스 부담을 줄일 수 있습니다. 기관의 기존 인증 체계를 확인해 결정합니다 |
| “물리 PC 2대를 쓰는 현재 구조가 비효율적입니다” | 단말 1대에서 업무용 가상 PC와 인터넷 환경을 분리해 사용하는 논리적 망분리 구조로 전환합니다. 배포·회수·유지보수는 중앙에서 일괄 처리합니다 |
| “공공 보안 요구사항 충족 여부를 증빙해야 합니다” | 국가정보원 보안기능확인서 · GS 1등급 · CSAP를 모두 보유한 제품 위에, 통제 항목별 구성 증빙을 산출물로 제공합니다 |
| “공공 도입 절차가 복잡합니다” | 조달청 디지털서비스몰 MAS 계약(CLOUDX 2.0) 기반으로 도입 절차를 단축합니다 |
| “표준 관리 화면이 기관 운영 방식과 맞지 않습니다” | Admin Portal을 기관 운영 방식에 맞춰 커스터마이징합니다. SKB Cloud PC Admin 포털을 직접 개발·고도화한 경험을 보유하고 있습니다 |
| “비상·재난 시 원격근무 좌석이 부족합니다” | 평시 좌석과 비상 좌석을 분리해 설계하고, 필요 시점에 확대 구축합니다 |

### Cloud X = VDI + 클라우드 인프라

가상 PC 제품 하나가 아니라 OpenStack과 Kubernetes 위에 VDI를 올린 구조입니다. 따라서 도입 이후 운영 범위에는 가상 PC뿐 아니라 클라우드 인프라 전체가 포함되며, 구축과 운영에 별도의 전문 인력이 필요합니다. 소프트웍스가 그 영역을 담당합니다.

![SK텔레콤 상품 자료, 단말 종류와 무관하게 중앙 서버의 자원을 동일한 환경으로 제공한다는 상품의 약속](../assets/cloudx/cloudx-concept.png)
*SK텔레콤 상품 자료, 단말 종류와 무관하게 중앙 서버의 자원을 동일한 환경으로 제공한다는 상품의 약속*

*도식 — Cloud X를 구성하는 네 개의 평면과 포털 아래 계층 전체에 해당하는 소프트웍스 수행 구간*

**도식 구성**: 제어 평면(Admin Portal · User Portal · 마이크로서비스) → 오케스트레이션(Kubernetes 위의 OpenStack 코어 구성요소인 Nova · Neutron · Cinder · Glance · Keystone) → 실행 평면(가상 PC 노드 수평 증설). 세 평면 전체를 가로지르는 별도 기둥으로 관리 평면(메트릭 · 로그 · 알람 · 이미지 관리)이 구성됩니다. 소프트웍스가 담당하는 구간은 포털 아래 계층 전부입니다.

| Pillar | 내용 |
|---|---|
| **제어 평면** | Admin · User 포털과 마이크로서비스 |
| **오케스트레이션** | Kubernetes 위의 OpenStack 코어 |
| **실행 평면** | 가상 PC 노드 수평 증설 |
| **관리 평면** | 메트릭 · 로그 수집을 별도 기둥으로 분리 |

## 07 CloudX 구성요소 — CloudX를 구성하는 여섯 개 구성요소

가상 PC 한 대가 기동하기까지 포털 · 인증 · 브로커 · 실행 노드가 차례로 관여합니다. 각 구성요소의 동작과 그에 앞서 소프트웍스가 결정하는 사항을 정리했습니다.

### Admin Portal — 관리 업무 전체를 단일 포털에서 수행합니다

대시보드 · 사용자 정보관리 · 사용자 지원 · 포털 관리 · 정책 관리 · 서비스 관리 · 가상 PC 관리 · 테넌트 자원관리 · 템플릿 관리 · 시스템 자원관리 · 모니터링 통계 · 관리자 설정을 기본 제공합니다. Super Admin과 Tenant Admin으로 권한을 구분해 운영 책임을 분리할 수 있으며, 대시보드는 담당자별로 구성을 달리하는 위젯형입니다.

*도식 — 12개 관리 메뉴와 Super Admin · Tenant Admin 권한 경계*

**소프트웍스가 하는 일** — 소프트웍스는 이 포털을 직접 개발·고도화해 온 조직입니다. 기관 환경에서는 인사 정보나 기존 업무 시스템과 연계해 계정을 자동 동기화하고, 2차 인증을 적용하며, 해당 기관에만 필요한 기능을 포털에 추가합니다. 테넌트 관리자에게 부여할 권한 범위도 함께 설계합니다.

### User Portal — 사용자는 브라우저만으로 접속합니다

사용자는 포털에서 로그인한 뒤 가상 PC 전원을 직접 켜고 끄며, CPU · 메모리 · 디스크 사용률을 확인한 다음 접속합니다. 클라이언트와 매뉴얼도 포털에서 직접 내려받습니다.

*도식 — 사용자 동선 5단계와 각 단계에서 관리자가 보유하는 통제 항목*

**소프트웍스가 하는 일** — 사용자가 직접 처리하는 구간이 넓어질수록 헬프데스크 부하가 감소합니다. 사용자에게 개방할 단계와 전원 스케줄, 세션 타임아웃 적용 방식을 기관 운영 방식에 맞춰 결정합니다.

### 접속 제어 계층 — 인증 경로와 화면 경로가 다릅니다

포털 로그인은 인증 서비스가 처리하고, 연결 브로커가 사용자와 가상 PC를 매칭한 뒤 전원·상태를 확인합니다. 실제 연결은 세션 게이트웨이를 거치며, 단말에는 화면만 전송되므로 데이터는 센터에 남습니다.

![SK브로드밴드 Cloud X 서비스 구성도, 단말로는 화면만 전송되고 센터로는 키보드·마우스·주변장치 입력만 전송되는 데이터 경로](../assets/cloudx/cloudx-service-arch.png)
*SK브로드밴드 Cloud X 서비스 구성도, 단말로는 화면만 전송되고 센터로는 키보드·마우스·주변장치 입력만 전송되는 데이터 경로*

*도식 — 접속 1회가 통과하는 인증 · 브로커 · 세션 게이트웨이 · 화면 전송 경로*

**소프트웍스가 하는 일** — 기관의 기존 인증 체계와 연계하는 방식, 외부 접속에만 2차 인증을 적용할지 여부를 설계 단계에서 결정합니다. 접속 1회가 통과하는 경로를 도식화하고 구간마다 통제 지점을 지정합니다.

### 자원 운영 — 가상 PC를 사전 생성하고 사용 후 초기 상태로 복원합니다

단일 골든 이미지로 가상 PC를 생성하고, 사용이 종료되면 초기 상태로 복원합니다. 대기 풀은 임계값에 따라 자동으로 증감하므로 사용자는 생성 대기 없이 즉시 할당받습니다.

*도식 — 임계값 기반 Scale Out / Scale In 자동 증설 및 회수 (임계값은 사업별 설정)*

**소프트웍스가 하는 일** — 접속 패턴을 근거로 이미지 구성 내용과 대기 풀 규모, 임계값 설정 지점을 결정합니다. 대기 풀을 과도하게 설정하면 자원이 유휴 상태로 남고, 부족하게 설정하면 출근 시간대에 할당 대기가 발생합니다.

### 이중화 구성 — 이중으로 구성하고 장애 발생 시 자동 전환합니다

제어 계층은 상호 상태를 지속적으로 확인하며, 이상이 발생하면 다른 서버로 전환되고, 운영 서버에 장애가 생기면 해당 서버의 가상 PC가 여유 자원이 있는 서버로 이관됩니다. 서비스망 · 관리망 · 스토리지망은 물리적으로 분리합니다.

*도식 — 장애 발생 시 관리 계층 전환과 가상 PC 이관 동작*

**소프트웍스가 하는 일** — 이관을 수용할 예비 자원을 설계 단계에서 미리 확보합니다. 서버 한 대에 장애가 발생해도 잔여 서버가 수용할 수 있는 범위에서 가상화 비율을 정하는 것이 핵심입니다.

### 보안 정책 — 관리자가 보안 정책을 항목별로 설정합니다

클립보드 · 파일 전송 · USB 슬롯별 허용 · 로컬 프린터 · URL 전달 · 화면 캡처 방지 · 워터마크를 항목별로 제어합니다. 구간 암호화는 기본 적용되며, 캡처 시도 시 가상 PC 영역만 가려집니다.

*도식 — 정책 제어 항목과 6개 보안 분야 대응*

**소프트웍스가 하는 일** — 규정 조항과 통제 항목을 매핑해 그룹별 적용 정책을 결정하고, 파일 반출입은 승인 절차를 거치도록 포털과 연계합니다. 감사 대응 증빙까지 산출물에 포함합니다.

## 10 Operation & Support

**구축 완료 후에도 현장 지원이 이어집니다**

사업 종료 후 일정 기간 전담 인력이 현장에 상주해 안정화를 지원하고, 이후 하자보수 기간이 이어집니다. 장애는 상주 인력이 1차로 접수하고, 해결되지 않는 사안은 구축팀과 제조사 기술 조직으로 단계별로 이관됩니다.

- 안정화 기간 전담 인력 현장 상주
- 1 / 2 / 3차 단계별 장애 대응 체계
- 단일 창구 접수 후 상주 인력 1차 처리
- 장애 이력 DB 기록 및 점검 항목 환류
- 정기 예방 점검
- 관리 포털 운영 대행
- 사용자 계정·자원 관리
- Admin Portal 기능 고도화 개발
- 조달 재계약 지원
